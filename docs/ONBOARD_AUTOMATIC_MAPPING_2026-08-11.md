# 板载自动建图实现说明（2026-08-11）

## 1. 当前实现范围

本版本在 FPGA 内持续完成位姿估计、RPLIDAR C1 射线融合和 128 x 128
占据栅格更新。地图分辨率为 50 mm，覆盖以初始点为中心的 6.4 m x 6.4 m
区域。已有 SD 卡保存/加载和蓝牙地图分块协议保持不变。

当前版本已恢复 FPGA 内的完整占据栅格，并增加板载轻量探索控制器。手机发送一次
场地配置帧、`O`、`J` 后，FPGA 会在双 IMU、陀螺极性和 RPLIDAR 扫描均有效时自主执行
短距离前进、停车观察、倒车脱困和择优原地转向。BLE 断开不会中断板载自动探索；
进入手机手动模式或发送 `K` 暂停建图会立即停止自主命令。

板载探索使用 8 方向局部距离和 App 下发的可调基站安全边界，不实现全图前沿搜索或 A*。
基于保存地图的目标点 A* 仍由手机端负责，以免把大规模优先队列和地图管理逻辑
放进 FPGA。离线时 FPGA 可以自主移动、融合并保存地图，重连后用原有分块协议同步。

## 2. 手机入口

Android 建图页已有“标定”按钮。点开后可选择：

- “仅运行板载闭环校准”；
- “板载校准后自动开始建图”。

手机只发送一次 `X`，后续校准动作由 FPGA 的本地状态机执行。第二个选项在
校准完成后发送 `O` 和 `J`，后续探索不再依赖手机周期重发运动命令。旧的直行
距离、左转角度和右转角度手工标定仍保留，但它们不是本地闭环校准。

## 3. 位姿质量门控

只有同时满足以下条件时，雷达点才能写入永久地图：

1. 双 IMU 启动校准完成；
2. 板载校准已确认陀螺仪左右转向极性；
3. 最近 100 ms 内收到过有效融合 IMU 样本；
4. 地图处于运行且未暂停状态；
5. 地图 RAM 未被清空或 SD 存储操作占用。

IMU 超时后仍可继续解析雷达串口，但点不会污染地图。新的融合 IMU 样本到达后，
建图自动恢复，不需要手机重新开始建图。

## 4. 陀螺仪温漂跟踪

四轮命令均接近零且原始角速度处于静止学习范围时，模块使用带 8 位小数的
1/64 IIR 观察器持续学习剩余 Z 轴静止偏置，包括地图运行期间。只有静止条件
成立才更新偏置，运动时自动冻结；校正后绝对值不超过 32 个 BMI088 原始计数的
样本进入航向死区，不再积成静止打转。真实转动仍按每个融合样本在 FPGA 内积分。

## 5. PMW3901 光流自学习与融合

模块不预设光流板的 X/Y 安装方向和正负极性：

1. 在连续直行或直退的 10 ms 窗口中收集 16 组数据；
2. 选择变化量明显较大的轴作为车体前向轴；
3. 根据前进/后退命令统一符号并确定光流正负极性；
4. 逐时钟搜索 `-4` 到 `+11` 的二进制比例指数；
5. 锁定后按“3 份光流 + 1 份轮速模型”融合每个前向位移窗口；
6. 光流方向不一致、幅度超过轮速预测两倍以上或质量无效时，自动回退到轮速模型；
7. 连续 32 个直行窗口不一致时丢弃旧标定并重新学习。

比例候选采用串行右移搜索，不构造 16 路 32 位组合选择器。一次搜索只需 16 个
50 MHz 时钟，而一个 10 ms 位姿窗口包含约 500000 个时钟，因此不会降低地图吞吐。

## 6. 雷达栅格融合

- 接收雷达点时锁存当时的车体栅格位置和朝向，避免长射线写入期间位姿变化；
- Bresenham 射线经过的单元将 log-odds 减 1，表示自由空间；
- 端点质量 `8..19`、`20..39`、`40..63` 分别将 log-odds 增 1、2、3；
- 低质量端点需要多次一致观测才能成为障碍，减少孤立噪点；
- 超出地图边界的射线仍清理到最后一个有效格，但不会把裁剪边界误写为障碍墙；
- 正、负方向毫米到栅格的转换使用对称四舍五入，修复原先 `+500 mm = +10 格`、
  `-500 mm = -11 格` 的左右不对称问题；
- 角度分箱增加半格舍入，确保 90/180/270 度进入正确的主方向扇区。

## 7. 状态与协议

已有地图状态和栅格分块上报继续使用原命令和帧格式。新增 17 字节场地配置帧由
App 在 `J` 前发送，内容包括板载地图初始位置、初始航向和基站安全边界；基站坐标
与 UWB 当前位置仍由 App 管理，因此更换比赛场地无需重新综合 FPGA。
`pose_flags` 的含义为：

| 位 | 含义 |
|---|---|
| bit0 | 双 IMU 校准完成 |
| bit1 | 陀螺仪转向极性有效 |
| bit2 | 光流比例已锁定且数据新鲜 |
| bit3 | 地图正在采集且未暂停 |
| bit4 | SD 存储正在占用地图 RAM |
| bit5 | 正在清空地图 |
| bit6 | 地图 RAM 内容有效 |
| bit7 | 本轮运行出现过丢弃样本 |

## 8. 仿真结果

`tb_onboard_automatic_mapping.v` 覆盖：

- 静止陀螺仪残余偏置收敛；
- PMW3901 前向轴、极性和比例指数学习；
- 光流/轮速 3:1 融合与异常回退；
- 未完成姿态校准时禁止地图写入；
- IMU 超时门控和新样本自动恢复；
- 低质量雷达点多帧累积；
- 越界射线不生成边缘假墙；
- 正负方向栅格投影对称。

关键结果：

## 9. 综合与 Robei 检查

- Robei 自带 Yosys：`synth_xilinx -abc9 -nodsp` 通过，`0 problems`；
- Vivado 2025.2 顶层综合、布局、布线和位流生成完成；
- 路由错误和未布线网络均为 0，全部时序约束满足；

这些结果证明当前 RTL 可以实现并已固化到 FPGA 配置 Flash；板载探索的实际运动轨迹、
地图精度和长期稳定性仍必须通过下一轮实车测试确认。

## 10. 板载探索安全逻辑

- 手动模式优先级高于板载探索；
- 地图暂停、IMU 未校准、陀螺极性无效、雷达离线或 1 秒无新扫描均输出停车；
- 前方或前角小于手机设置的安全距离时禁止继续前进；
- 后方可用时先短倒车，再向左右净空更大的一侧原地转向；
- 后方受阻时不倒车，直接选择净空更大的转向侧；
- 每次前进 160 ms、倒车 120 ms、转向 300 ms；动作后至少停车 650 ms，且必须
  等到一帧新的雷达扫描才重新决策，让手机雷达/地图显示有时间同步；
- 车体接近 App 下发的基站矩形安全边界时禁止继续朝边界前进；雷达点仍可记录在
  基站矩形外，只限制自动探索运动不越界。

## 12. 下一次实车验证顺序

1. 将小车放在平整、空旷区域，确保双 IMU、PMW3901 和雷达均在线；
2. 在手机建图页选择“板载校准后自动探索建图”；
3. 保持车体四周有足够空间，观察校准完整结束且 `pose_flags.bit0..2` 有效；
4. 先低速直行、后退和原地转向，检查手机地图中墙面是否保持固定；
5. 若墙面随车漂移，记录直行 1 m、原地 360 度和矩形闭环后的位姿误差；
6. 实测通过后再增加扫描匹配、地图闭环校正和 A* 目标点寻路；当前板载控制器已经能完成轻量避障探索。
