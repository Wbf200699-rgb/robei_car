# 无 ARM 小车定位、稳定控制与建图完善方案

> 注意：本文件记录早期以 UWB/服务器参与全局校正和建图的方案。当前正式方向已改为 FPGA 本地标定、建图、Flash 保存和寻路，UWB 只作为研发真值监视。后续实施以 `docs/LOCAL_MAPPING_FLASH_NAVIGATION_PLAN.md` 为准。

## 1. 当前可确认基础

当前已经具备并分别验证的链路如下：

1. C5 四轮串口控制、停车保护、手动模式和参数回传已在主工程中工作；
2. RPLIDAR C1 能启动并向 FPGA 返回数据，超声波避障保持独立安全链路；
3. CH9141K 蓝牙能承载手机控制和现有 `@S/@L` 状态协议；
4. LinkPG 四基站、四标签已输出四标签二维定位，ESP32-CAM 能把数据送到服务器；
5. 车载标签 1 与 FPGA 的 N14/N13 双向 UART 已通过请求/应答实测；
6. PMW3901 与两块 BMI088 已由独立 FPGA 固件同时识别，静止融合状态正常。

INA226 和 VL53L1X 暂缓接入，不分配主工程资源，也不作为以下阶段的前置条件。

## 2. 分层架构

```text
实时安全层（FPGA，50 MHz）
  超声波 + RPLIDAR近场判定 -> 矩形车体避障 -> C5速度命令与停车保护
  双BMI088 -> 偏置校准/一致性判断 -> 角速度与短时航向
  PMW3901 -> 质量门限/坐标变换 -> 车体平面增量
                       |
                       v
  100 Hz固定点里程计：位置预测、航向预测、异常降级

全局定位层（LinkPG + ESP32-CAM + 服务器）
  四标签坐标 -> 新鲜度/同步性/矩形刚性检查 -> 车体中心与全局航向
                       |
                       v
  低频全局校正、轨迹记录、地图坐标系

交互层（手机）
  手动/自动模式、参数设置、状态诊断、轨迹和栅格地图显示
```

FPGA负责确定时延的采样、保护和局部估计；服务器负责全局坐标验证、历史
轨迹和地图。即使 Wi-Fi/UWB 网关离线，FPGA 的停车、超声波和雷达避障仍然
独立工作。服务器 ACK 只表示命令经过某一传输阶段，实际车辆状态以 FPGA
最新 `@S` 为准。

## 3. FPGA 侧估计算法

### 3.1 双 IMU

- 两块 BMI088 使用相同量程、带宽和轴方向；启动静止 512 样本估计陀螺偏置。
- 两块均在线且差值在门限内时取平均；一块异常时退化为单块，并置位
  `imu_degraded`；两块有效但持续分歧时冻结航向校正并置位
  `imu_disagreement`。
- 航向采用定点积分：`yaw += gyro_z_corrected * dt`。第一版不实现完整 EKF，
  避免大规模乘法器和高扇出组合逻辑给 Robei 布线增加压力。
- 静止检测条件由低光流、低角速度和加速度模长接近 1g 共同决定；连续静止
  后允许缓慢更新陀螺零偏，运动时禁止更新。

### 3.2 光流里程计

- 只有 `online=1`、SQUAL 达标且单帧增量未越界时才接受 PMW3901 数据。
- 标定后使用每轴比例和安装旋转矩阵，把 `delta_x/delta_y` 转成车体毫米增量。
- 由陀螺航向把车体增量旋转到地图坐标：
  `dx_world = dx_body*cos(yaw) - dy_body*sin(yaw)`，
  `dy_world = dx_body*sin(yaw) + dy_body*cos(yaw)`。
- FPGA 中使用查找表或分段定点近似实现正余弦，不使用 Vivado IP 核。
- SQUAL 过低、镜头遮挡或累计溢出时只保留 IMU 航向，不累加平移位置。

### 3.3 低资源融合

采用“高频预测、低频校正”的互补结构：

1. 100 Hz 使用光流和陀螺更新局部 `x/y/yaw`；
2. 服务器只有在四标签新鲜、同步且矩形检查通过时才生成 UWB 全局校正；
3. 校正量按限幅增益逐步注入，不能一次跳变到底盘控制坐标；
4. UWB 短时丢失时继续局部里程计，超过超时只降低定位质量，不关闭避障；
5. 光流失效时 UWB 保持全局位置，IMU 保持短时航向；两者都失效时禁止自动
   导航，但保留人工低速脱困和安全停车。

## 4. UWB 与服务器数据质量

四标签融合必须同时满足：

- 每个标签 `position_valid=1`；
- 单标签年龄不超过 0.6 s；
- 四标签最老与最新样本差默认不超过 0.15 s；
- 前后宽度、左右长度与实测车体标签中心距在容差内；
- 后续增加两条对角线长度和连续速度门限，用于剔除瞬时跳点。

服务器输出质量等级：`none`、`partial`、`unsynchronized`、
`unconfigured`、`rejected`、`full`。只有 `full` 可以进入自动导航或地图
校正。手机必须同时显示网关连接、数据新鲜度和质量等级，不能只依据 WebSocket
是否连接。

## 5. 建图数据量方案

当前 8 方向雷达数据足够避障和粗略雷达图，不足以生成精细墙面地图。建图路径
升级为 72 个 5 度角度箱，与原有 8 扇区安全路径并行：

- FPGA 每个角度箱选择最接近箱中心的有效点，不使用容易把墙面拉近的最小值；
- 一点压缩为 12 bit，包含约 16 mm 步长的距离和 2 bit 质量等级；
- 12 点组成一个 50 字节 `@R` 行，六行组成一圈，默认 2 Hz 上报；
- 每圈带扫描序号、10 ms 时基、分包号和 CRC-8，缺包时丢弃整圈；
- 服务器按点的采样时刻和车辆全局位姿把极坐标投影到 50 mm 栅格；
- 使用有界占用概率更新栅格，不在 FPGA 内保存整幅地图；
- UWB 或运动姿态质量不足时只显示即时雷达，不写入永久地图。

完整协议、外参标定、运动畸变补偿、资源目标和验收证据见
`docs/LIDAR_MAPPING_UPGRADE.md`。这样把确定时延的采样和压缩留在 FPGA，
把随时间增长的地图存储和墙线拟合留在服务器，不依赖 ARM 核心参与小车实时
控制计算。

## 6. 分阶段实施与验收

### 阶段 A：传感器参数标定

1. 静止 60 s，记录两块 IMU 噪声、偏置和温漂；
2. 手工依次绕 X/Y/Z 正方向旋转，确定两块板与车体轴映射；
3. 光流镜头沿车体 X、Y 各移动 500 mm 和 1000 mm，计算每毫米计数；
4. 原地旋转 90/180/360 度，检查光流旋转耦合和陀螺积分误差；
5. 电机架空和落地分别采样，确定电机振动下的分歧门限。

采集、自动判定和参数固化条件见
`docs/MOTION_SENSOR_CALIBRATION_PROCEDURE.md`。2026-08-04 的即时预检仍能
收到连续 `@M`，但光流 `SQUAL=0` 且车体存在明显角速度扰动，因此阶段 A
尚未完成，不能把当前样本写入闭环参数。

### 阶段 B：主工程只读接入

把运动传感器模块接入 Robei 主图，但第一版只输出在线、质量、原始增量和融合
角速度，不参与 C5 控制。重新检查 ABC9、Roplace、时序和 HDMI 稳定性；资源
或布线明显恶化时拆成较低采样率或减少调试字段。

进入本阶段前还要解决主工程资源基线：当前完整结构由 Vivado 2025.2 映射为
36,253 个 LUT，超过 XC7A50T 的 32,600 个逻辑 LUT；Robei/Yosys 的映射口径
和结果不同，不能用其中任意一份报告替代实际 Roplace 结果。不得关闭 Vivado
资源 DRC 强行生成 bit，也不得在资源基线未重新闭环时把运动传感器直接接入
C5 控制。

### 阶段 C：局部里程计

固化标定参数，增加定点 `x/y/yaw`，通过蓝牙/UWB 以低频状态帧上报。先用手推
轨迹验证闭环误差，再允许电机低速直线和原地转向验证。

### 阶段 D：UWB 全局校正

四标签固定到车体四角，录入 ID 与前后左右角色及实测中心距。服务器质量达到
`full` 后才启用全局轨迹；校正只影响导航估计，不绕过 FPGA 避障和停车保护。

### 阶段 E：精细雷达建图

在阶段 D 的全局坐标稳定后增加 72 点压缩协议和服务器栅格更新。先离线回放
验证，再开放实时地图；不在定位质量不足时累积地图。原有 8 扇区避障路径保持
独立，地图发送拥塞或丢包不得影响控制确认、心跳和停车保护。

## 7. 下一轮实物操作

当前 FPGA 运行的是独立运动传感器验证固件，不是小车主固件。下一轮需要保持
车轮架空，按阶段 A 做有明确方向和距离的动作；每个动作单独保存 CSV。完成轴
方向和比例标定后，才能把参数写入 Robei 主模块并恢复主车固件。
