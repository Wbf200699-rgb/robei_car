# FPGA 本地标定、建图、Flash 保存与自动寻路方案

## 1. 结论

可以实现，并且不需要 ARM 核心参与车端计算。推荐保留以下职责边界：

- FPGA：传感器采样、姿态和位移估计、雷达匹配、栅格建图、Flash 保存、路径规划、路径执行和安全停车；
- Android：通过 CH9141K 蓝牙显示地图、选择起点和终点、发起标定/保存/加载/规划/运行命令；
- UWB + ESP32-S3 + 服务器：仅作为研发阶段的外部真值、轨迹监视和误差评估，不进入正式控制闭环；
- 超声波和现有雷达近场避障：继续作为独立安全链路，任何地图或规划状态都不能绕过它们。

能否稳定运行的关键不在地图容量，而在本地位姿。C5 底盘的 AB 编码器没有对外开放，因此正式方案必须依靠 PMW3901 光流、BMI088 航向和 RPLIDAR 扫描匹配共同抑制漂移。只有 IMU 或只有雷达都不足以稳定复用保存后的地图。

## 2. 当前工程基线

当前主工程保留：

- C5 四轮控制和停车保护；
- RPLIDAR C1 启停、避障、72 点扫描压缩和蓝牙上报；
- 超声波避障；
- CH9141K 蓝牙控制、状态和参数回传；
- HDMI 状态显示；
- Android 雷达图、占用栅格、运动标定和探索界面。

当前主工程已经移除 LinkPG/UWB 对蓝牙命令和雷达上报的转接。UWB 调试代码仍可作为独立诊断固件使用，但不注册到 Robei 主图，也不消耗正式固件资源。

PMW3901 和两块 BMI088 已有独立 `motion_sensor_subsystem` 模块和实物验证记录，但尚未接入当前车辆主图。下一阶段必须先做只读接入，确认资源和布线后再参与导航。

### 2.1 当前资源风险

2026-08-05 的 Vivado 综合结果：

| 项目 | 使用量 |
|---|---:|
| Slice LUT | 34,924 / 32,600 |
| Slice Register | 4,330 / 65,200 |
| RAMB18 | 2 / 150 |
| DSP48E1 | 5 / 120 |

Robei/Yosys 采用不同的 LUT5/LUT6 打包口径，现有工程曾以约 66% 的 `SLICE_LUTX` 完成布线，所以不能把两份比例直接相比。但 Vivado 已明确说明组合逻辑余量很差。最大模块为：

| 模块 | Vivado LUT |
|---|---:|
| `route_contol_core` | 14,389 |
| `car_param_controller` | 6,565 |
| `hdmi_timing_gen` | 5,780 |

因此不能把建图算法写成大数组组合比较、组合除法或一拍完成的全图搜索。应先把上述模块中的变量除法、宽比较和大选择器改成常量移位、顺序状态机或 BRAM 查表，再接入导航模块。目标是正式加入导航前，把 Robei 实际布线 LUT 控制到 75% 以下。

## 4. Robei 模块划分

所有新增逻辑都先写独立 Verilog，再转换为同名 `.model`，最后在 Robei 顶层显式连线。不要把算法直接塞进 `sys_route_gui_fsm_top.model` 的顶层 Code。

| 模块 | 作用 | 实现原则 |
|---|---|---|
| `motion_sensor_subsystem` | PMW3901 和双 BMI088 采样 | 复用现有 SPI 状态机 |
| `local_pose_estimator` | 固定点 `x/y/yaw` 预测和质量判定 | 逐周期乘加，正余弦查表 |
| `lidar_scan_matcher` | 用当前扫描校正局部位姿 | 小范围穷举，单候选/单点流水 |
| `occupancy_grid_map` | 射线清空和端点占用更新 | BRAM 单元读改写，不展开全图 |
| `flash_spi_controller` | MT25QL128 读、页写、扇区擦除、状态轮询 | 自研 SPI，不使用 IP 核 |
| `map_store_manager` | A/B 槽、版本、CRC 和掉电一致性 | 先写数据，最后提交有效头 |
| `obstacle_inflator` | 按车体轮廓扩张障碍 | 顺序两遍或预计算掩模 |
| `wavefront_planner` | 从终点反向生成距离场 | BRAM 队列，无优先堆 |
| `path_compactor` | 把逐格路径压成直线/转向段 | 最多保存有限段数 |
| `path_executor` | 跟踪路径并生成底盘命令 | 只产生请求，最终仍经过安全层 |
| `navigation_supervisor` | 标定、建图、保存、规划、运行和故障状态 | 明确状态与超时，不与 HDMI 共用状态机 |

## 5. 本地自动标定

### 5.1 静止标定

上电后车辆保持不动 3 至 5 秒：

1. 两块 BMI088 各自累计陀螺零偏和噪声；
2. 检查两块 IMU 的方向、幅值和一致性；
3. PMW3901 检查 `SQUAL`、静止漂移和镜头遮挡；
4. 只有静止条件连续成立才提交参数，车辆被碰动则重新计时；
5. 参数带温度、样本数、方差和 CRC 保存，不能只保存平均值。

### 5.2 光流尺度和安装角

绝对尺度不能只靠光流自己推导。可在有墙角和纹理地面的区域低速移动，用 RPLIDAR 相邻扫描匹配得到毫米级平移参考，再拟合：

- X/Y 每毫米计数；
- 光流模块相对车体的安装旋转；
- 前后运动与横移的交叉耦合；
- `SQUAL` 门限和最大可信单帧增量。

环境没有稳定几何特征时应拒绝自动标定，并提示换到有墙面、地面有纹理的区域。研发阶段可以同时记录 UWB 真值做离线验证，但正式参数不能依赖 UWB 在线。

### 5.3 电机标定

在用户确认安全区域后自动执行低速短动作：

1. 四轮中位和死区确认；
2. 直行时根据 IMU 航向变化和雷达/光流横向漂移迭代左右轮修正；
3. 原地左右转，根据实际角度计算转向速度和持续时间系数；
4. 每次只修改小步长，并保留上一份有效参数用于失败回退；
5. 现有超声波和雷达避障始终有效，失去定位质量立即停车。

## 6. 本地建图

### 6.1 地图格式

第一版沿用 Android 当前坐标尺度：

- `201 x 201` 单元；
- `50 mm` 分辨率；
- 覆盖约 `10 m x 10 m`；
- 每格使用 4 bit 有符号饱和占用分数；
- 原始地图约 20 KiB，约占 5 个 RAMB36；
- 另设 1 bit 扩张障碍图、访问图和规划队列，整个导航模块预计使用 15 至 25 个 RAMB36，XC7A50T 的 75 个 RAMB36 容量足够。

4 bit 分数比简单的未知/空闲/占用三态更抗单帧噪声。雷达射线经过的单元递减，端点递增，达到门限后才成为规划障碍。

### 6.2 位姿更新

1. 100 Hz 用光流平移和 IMU 角速度预测位姿；
2. 每圈雷达只在预测位姿附近搜索，例如 X/Y 各 5 个候选、航向 7 个候选；
3. 每个候选顺序读取 72 个雷达端点在地图中的占用得分；
4. 最佳与次佳分数差不足、有效点太少或运动过快时不接受校正；
5. 校正采用限幅增益逐步注入，避免位姿瞬间跳变；
6. 先完成匹配，再把这一圈写入地图，避免当前扫描给自己制造虚假高分。

按 `5 x 5 x 7 x 72 = 12,600` 次查询估算，50 MHz 下采用顺序流水仍远低于一圈雷达的时间预算，资源压力主要是 BRAM，不是算力。

## 7. 板载 Flash

`A7-50T资源约束表.xlsx` 把用户可访问的板载器件标为 `W25Q128`。需要注意，
2026-08-06 通过 Vivado/JTAG 读取到的 `20 BA 18` 来自 FPGA 专用配置接口上的
`MT25QL128`，不能据此认定下表这颗用户 Flash 也是同一芯片。用户逻辑必须通过
资料表给出的六根普通 GPIO 访问，并同时接受 Winbond 与 Micron 的 128 Mbit
JEDEC ID：

| 信号 | FPGA 管脚 |
|---|---|
| CS# | E18 |
| CLK | D16 |
| DO/MISO | C17 |
| DI/MOSI | C18 |
| IO2 | D17 |
| IO3 | J16 |

该用户 Flash 为 128 Mbit，也就是 16 MiB。它与 Vivado/JTAG 使用的专用配置
Flash 接口不同；地图区仍只允许访问顶部预留双槽，并保留硬件地址保护：

1. 先做只读探测固件，读取 JEDEC ID、状态寄存器和 SFDP；
2. 确认地图双槽地址没有与板载其他用途重叠；
3. 任何擦除命令都必须经过地址范围硬件比较器，双槽之外的地址永远拒绝写入。

本板资源表中的 Flash `CLK=D16` 是 Bank 16 普通用户 IO；当前器件封装的专用
`CCLK_0` 实际位于 `L12`。因此用户 Flash 时钟必须作为顶层 `flash_clk` 输出约束
到 D16，不能通过 `STARTUPE2`。该方案不使用 Vivado IP 核，并且必须在
Robei/Yosys 与 Vivado 两条流程中分别验证顶层端口、连线和管脚映射。

### 7.1 数据布局

标定参数和每份地图均使用双槽提交：

```text
header:
  magic, format_version, sequence, state
  width, height, resolution_mm, origin_x, origin_y
  start_x, start_y, start_heading
  calibration_version, payload_length, payload_crc32

payload:
  4-bit occupancy cells
  optional compressed path and landmarks

commit:
  header_crc32 and VALID marker, written last
```

保存时写入较旧的槽，校验读回后最后写 `VALID`；启动时选择 CRC 正确且序号最新的槽。断电发生在擦除或写入中也不会破坏另一份地图。

## 8. 路径规划和执行

### 8.1 第一版规划器

第一版使用波前 BFS/Lee 算法，不使用带优先堆的 A*：

- 从终点向外扩散距离；
- 每周期处理一个相邻单元；
- 完成后从起点沿距离下降方向回溯；
- 把连续同方向单元压缩为直线段和转向段；
- 规划超时、队列满、起终点被占用或无路径都返回明确错误，车辆保持停车。

第一版用车体外接圆加安全余量扩张障碍，优点是逻辑简单且不会让矩形车角碰撞。第二版再增加 `x/y/8方向` 状态格，按真实长方形在不同方向的扫掠轮廓规划，可通过较窄通道，但状态数和 BRAM 增加约 8 倍。

### 8.2 手机选择起点和终点

加载保存地图后，手机在地图上选择：

- 起点单元和初始朝向；
- 目标单元；
- 仅规划或规划后运行。

显式选择起点是必要条件。没有 UWB 或外露轮编码器时，车辆重新上电后无法仅凭一帧雷达在重复走廊中唯一确定全局位置。FPGA 先使用手机给定的近似起点，再用保存地图做小范围雷达重定位；匹配质量不足时拒绝自动运行。

后续蓝牙扩展协议建议使用带前缀、长度、序号和 CRC 的多字节命令，保留现有单字符手动控制。例如：

```text
:NS,<x>,<y>,<heading>,<seq>,<crc>\n   设置起点
:NG,<x>,<y>,<seq>,<crc>\n             设置终点
:NP,<seq>,<crc>\n                     开始规划
:NR,<seq>,<crc>\n                     执行路径
:NA,<seq>,<crc>\n                     中止并停车
:MS,<slot>,<seq>,<crc>\n              保存地图
:ML,<slot>,<seq>,<crc>\n              加载地图
```

协议尚未在本次清理中加入，避免在导航状态机完成前破坏现有手机兼容性。

### 8.3 路径执行

路径执行不是按时间盲走：

- 直线段由光流累计距离控制，IMU 航向闭环修正左右速度；
- 转向段由 IMU 角度控制，雷达匹配用于低频校正；
- 每段设置最大时间、最大位姿不确定度和停止确认；
- 发现新障碍先停车，更新局部地图后重新规划；
- 定位质量下降、Flash 错误、蓝牙断开不直接导致失控，自动模式退出并发送诊断状态。

## 9. 实施顺序和验收

### 阶段 0：资源瘦身

- 重写三个高 LUT 模块的高成本组合运算；
- 保持 HDMI、蓝牙和电机功能不变；
- Robei 完整布线后 LUT 目标低于 75%。

### 阶段 1：主图接入运动传感器

- 只读接入 PMW3901 和双 BMI088；
- 输出在线、质量、原始量和偏置，不影响电机；
- 完成 Robei 模型、Verilog、仿真和实物串口证据。

### 阶段 2：Flash 只读和受限写入

- 读取 JEDEC/SFDP；
- 确认配置镜像边界；
- 只在预留测试扇区做擦写和掉电恢复测试；
- 加入硬件地址防护后才允许地图保存。

### 阶段 3：本地位姿和自动标定

- 手推直线、方形、原地 360 度测试；
- 与 UWB 测试真值对比，但 FPGA 算法不读取 UWB；
- 固化光流、IMU、雷达外参和电机修正参数。

### 阶段 4：BRAM 建图和 Flash 保存

- 手机实时显示 FPGA 生成的地图；
- 保存、断电、加载后地图 CRC 和内容一致；
- 地图上报堵塞不能影响 `@PONG`、状态帧或停车命令。

### 阶段 5：手机选点和自动寻路

- 手机选择起点、方向和终点；
- FPGA 返回规划状态、路径长度和错误原因；
- 实车先架空验证，再低速地面验证；
- 任何避障、定位质量或看门狗异常都必须在电机层停车。

## 10. 开工门槛

开始正式本地导航前必须同时满足：

1. 当前清理版在 Robei 完整布线并上板验证蓝牙、HDMI、雷达和电机无回归；
2. PMW3901 在实际安装高度和地面上持续获得有效 `SQUAL`；
3. 双 BMI088 轴方向、静止偏置和电机振动数据已固化；
4. MT25QL128 已完成只读识别，地图预留区不会覆盖配置镜像；
5. 现有组合逻辑先完成资源瘦身。

满足这些门槛后，该方案在 XC7A50T 的 BRAM、DSP 和时钟性能范围内可行。当前真正的风险是 LUT 布线余量和位姿质量，而不是 Flash 容量或路径搜索速度。
