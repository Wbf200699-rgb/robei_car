# 统一验证模型、运动标定与 VL53L1X 接入状态

## 1. 坐标系与唯一配置源

所有软件默认值由 `config/vehicle_geometry.json` 生成。修改几何后运行：

```powershell
python tools\generate_vehicle_geometry.py
python tools\generate_vehicle_geometry.py --check
```

统一世界坐标系：

- 原点：地面基站 A；
- `+X`：A 指向 C，即场地向右；
- `+Y`：A 指向 D，即场地向上；
- 基站从左上角顺时针为 D、B、C、A。

| 基站 | X/m | Y/m | 说明 |
|---|---:|---:|---|
| A | 0.00 | 0.00 | 左下，世界原点 |
| B | 1.50 | 1.67 | 右上 |
| C | 1.50 | 0.00 | 右下 |
| D | 0.00 | 1.67 | 左上 |

因此 `DB=1.50 m`、`BC=1.67 m`。服务器采用这套坐标并不等于 LinkPG
基站已经写入这些坐标；实测前仍需在上位机中确认 A/B/C/D 配置一致。

统一车体坐标系：

- 原点：四根 UWB 天线构成矩形的对角线交点；
- `+X`：车头方向；
- `+Y`：车体左侧；
- `+Z`：向上。

| 位置 | 标签 | 车体系 X/m | 车体系 Y/m |
|---|---:|---:|---:|
| 左前 | 1 | +0.110 | +0.100 |
| 右前 | 2 | +0.110 | -0.100 |
| 右后 | 3 | -0.110 | -0.100 |
| 左后 | 0 | -0.110 | +0.100 |

标签矩形长 `0.22 m`、宽 `0.20 m`。两个 BMI088 目前只确认位于纵向中点，
横向偏移、安装旋转和高度尚未测量。PMW3901 暂按二层中心、离地 `0.105 m`
记录；“中心到车尾约 0.20 m”作为车体尺寸备注，不用于当前外参计算。

## 2. UWB 的用途边界

UWB 仅作为研发阶段外部真值，不进入 FPGA 安全或运动闭环。四标签矩形的短边
为 20 cm，而 UWB 单标签噪声与该基线同量级，因此：

- 可用于 0.4 m 以上运动段的平均速度、累计位移和低频航向误差评估；
- 静止前后各取至少 9 组/标签并做中值滤波；
- 单帧刚体残差异常时整帧拒绝；
- 不用于高频 PID 反馈，也不替代 BMI088；
- PID 调参需要 BMI088 的 100 Hz 以上时间序列，UWB 只检查长期漂移。

Android 已有纯 Java 的四标签刚体拟合、静止窗口中值、运动参数鲁棒估计、
25 mm 占用栅格和局部扫描匹配参考实现。调试 APK 使用独立包名
`car.car_app.debug`，不会覆盖正式应用。调试版启动时还会在手机进程中执行一轮
确定性的几何、标定、建图和扫描匹配回放；结果写入 App 日志和 logcat 标签
`VehicleAlgorithm`。

## 3. 下一次实车标定摆放

需要采集真实数据时，把车体中心先放在约 `(0.75 m, 0.835 m)`，车头朝 `+X`
（从 A/D 一侧朝 C/B 一侧），保持四周无人员遮挡。不要立即自动运行，先依次做：

1. 静止 10 秒，确认四标签持续新鲜、刚体拟合没有频繁拒绝。
2. 轮子悬空，验证停止、正反转和四轮方向，不采位移参数。
3. 落地后低速前进 0.4 至 0.5 m，重复 5 次；每次动作前后静止 2 秒。
4. 低速左转和右转，各做 45 至 90 度，重复 5 次。
5. 光流/BMI 数据稳定后，再做直行偏航修正和航向 PID 阶跃实验。

第 3、4 步会由调试 App 持续刷新手动命令并发送停止，但在开始前必须再次确认
场地已清空、电池正常且车轮没有顶住障碍。

## 4. 五路 VL53L1X 当前实现

已经完成但尚未接入车辆顶图：

- 单个开漏 I2C 主机，16 位寄存器地址，支持 1/2 字节读取；
- 五路 XSHUT 顺序上电；
- 默认地址 `0x29` 依次改为 `0x30..0x34`；
- 每路写入官方包 `0x002D..0x0087` 的 91 字节配置；
- 首次测距、VHV 复用、连续测距、数据就绪轮询、距离读取和清中断；
- 每路 3 点中值滤波；
- 前/左/右/后方向使用可配置 5 位掩码，不提前猜安装方向。

要接入正式顶层，还缺以下实物记录：

| 信号 | 需要提供的内容 |
|---|---|
| I2C SCL | FPGA 管脚名和连接器针脚 |
| I2C SDA | FPGA 管脚名和连接器针脚 |
| XSHUT0..4 | 五个 FPGA 管脚及其对应模块编号 |
| 模块 0..4 | 每块朝向，例如前、左前、右前、左、右或后 |
| 供电 | 确认模块电源电压、公共地和板载上拉电压 |

在这七根信号确认前，不修改 `top.const`、`top.xdc` 或
`sys_route_gui_fsm_top.model`，以免覆盖已验证的 HDMI、蓝牙、雷达和电机接口。

| 项目 | 结果 |
|---|---|
| GUI 烟雾仿真 | 颜色、边框、目标点、BT 状态和动态十进制文字通过 |

| 正式顶层综合 | 34,924 LUT 降为 15,513 LUT，占 47.59% |
| 正式顶层布局布线 | 15,361 LUT（47.12%）、4,489 FF，18,212 条网络全部布通，路由错误 0 |
| 正式顶层 bitstream | `little_car/build/vivado_main/sys_route_gui_fsm_top.bit` 生成成功；尚未烧录 |
| VL53 I2C 写 | `52,12,34,AB` 帧通过 |
| VL53 I2C 读 | 寄存器 `0x0096` 返回 500 mm 通过 |
| 五路初始化 | 5 次改址，每路 91 字节配置，10 次启动，通过 |
| 五路融合 | 中值滤波、方向掩码、最近距离和障碍位通过 |
| Android | 14 项单元测试通过，debug APK 真机启动并输出 `VehicleAlgorithm: PASS` |
| Android 真机回放 | 位姿 `(0.750,0.835,23.0deg)`、直行 `0.300mm/ms`、转向 `0.178/0.184deg/ms`、地图 `64/619`、匹配增益 `252` |

不含五路 VL53L1X 顶层连接，在实物管脚和朝向确认前不得用它验证激光模块。
