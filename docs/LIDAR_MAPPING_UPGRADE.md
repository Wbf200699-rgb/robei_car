# RPLIDAR C1 精细建图升级方案

## 1. 目标与边界

这里的“提高雷达精度”分成三件事：

1. 保留比当前 8 个方向更多的角度信息，提高地图的角分辨率；
2. 通过质量筛选、外参标定和运动畸变补偿，提高点落到全局地图后的准确性；
3. 通过多帧栅格融合降低随机噪声。

FPGA 不能改变 RPLIDAR C1 本身的物理测距极限，因此不能把“增加扇区数”直接
等同于“传感器测距更准”。当前 8 个 45 度扇区继续只服务实时避障；精细建图
使用独立数据路径，不改变超声波保护，也不把地图保存在 FPGA 内。

INA226 和 VL53L1X 继续暂缓，不属于本方案的前置条件。

## 2. 当前实现状态

`rplidar_c1_uart` 已经解析并输出以下逐点数据：

- `sample_valid`：一个完整测量点已经解析；
- `new_scan`：新一圈扫描开始；
- `quality[5:0]`：RPLIDAR 节点质量；
- `angle_q6[14:0]`：角度，单位为 1/64 度；
- `distance_q2[15:0]`：距离，单位为 1/4 mm。

主顶层现在同时使用这五个逐点端口和原有 8 扇区输出：`@L` 继续服务避障、
诊断和粗略雷达图，新增 `lidar_map_sampler` 把逐点数据压缩为 72 个 5 度角度箱，
再通过 `@R` 分包送往蓝牙和 LinkPG UWB。两条路径互不替代，建图上报拥塞或
丢包不会暂停 FPGA 本地避障。

## 3. 双路径雷达处理

### 3.1 安全路径保持不变

- 8 个 45 度扇区；
- 每扇区取近距离并做三圈中值；
- 前方、前角和侧面按矩形车体保护距离判定；
- 直接进入 FPGA 电机禁止逻辑；
- 不依赖手机、UWB、ESP32-CAM 或服务器。

### 3.2 建图路径

第一版采用 72 个 5 度角度箱，每圈最多输出 72 个代表点：

1. 丢弃质量为 0、距离小于 50 mm 或大于 12000 mm 的节点；
2. 在每个 5 度角度箱中选择最接近箱中心的有效点；
3. 质量过低的点可显示在即时雷达图，但不得写入永久栅格；
4. FPGA 只做筛选、压缩和分包，不做三角函数、栅格射线或墙线拟合；
5. 服务器结合车辆位姿完成坐标变换、运动补偿和多帧融合。

选择“靠近角度箱中心的点”而不是“最小距离”，是为了避免地图墙面被偶发近距
噪声系统性向车体方向拉近。安全路径仍然可以使用最小距离，因为两条路径的
风险目标不同。

## 4. 低资源 FPGA 结构

当前实现增加 `lidar_map_sampler` 并复用统一串口调度，没有复制 RPLIDAR UART
接收器：

```text
rplidar_c1_uart raw point
        |
        +--> existing 8-sector safety filter --> obstacle_stop
        |
        +--> lidar_map_sampler
               | 72 x 12-bit packed scan buffer
               v
          six @R chunks --> existing serialized TX queue
                            |--> CH9141K
                            `--> LinkPG UWB bridge tap
```

资源控制原则：

- 每个缓存项保存有效位、角度误差和 12 bit 压缩点；两组 72 项乒乓缓存分别
  推断为一块 `RAMB18E1`，不使用 IP 核；
- 每个时钟只处理一个雷达点，不生成 72 组并行除法器或中值比较器；
- 5 度等于 Q6 格式的 320，角度箱可用递增边界比较实现，避免通用除法；
- 串口发送必须进入现有统一调度，`@S/@L/@K/@PONG/@R` 均保证整帧发送，
  不允许字节交叉；
- 心跳和控制确认优先于地图帧，地图拥塞时允许丢弃整圈，不能阻塞停车命令。

模块级 Robei/Yosys 验证结果为 598 个估算 LC、424 个 `FDCE`、0 DSP 和
2 个 `RAMB18E1`，达到不超过 600 LC、1000 FF、0 DSP、2 个 BRAM18 的目标。
完整顶层的实际资源和布局结果见第 9 节。

## 5. 建图帧协议

新增 ASCII 行，不修改现有 `@S` 和 `@L`：

```text
@R1SSTTTTPN<DDD x 12>CC\n
```

字段定义：

| 字段 | 长度 | 含义 |
| --- | ---: | --- |
| `R1` | 2 | 雷达建图协议版本 1 |
| `SS` | 2 | 8 bit 扫描序号 |
| `TTTT` | 4 | 10 ms 单位的 16 bit FPGA 时基 |
| `P` | 1 | 分包编号，0 至 5 |
| `N` | 1 | 总包数，固定为 6 |
| `DDD x 12` | 36 | 连续 12 个 12 bit 压缩点 |
| `CC` | 2 | 从 `R` 到最后一个点字段的 CRC-8 |

每行共 50 字节（包含 `@` 和换行），小于 LinkPG 单片段 64 字节数据上限。
一圈固定六行，只有六行序号一致且 CRC 全部正确时，手机或服务器才提交整圈；
缺少任意一行就丢弃整圈，不能拿旧分包补新扫描。

每个 `DDD` 的 12 bit 布局：

```text
[11:10] quality_class
[ 9: 0] distance_code
```

- `distance_code = round(distance_mm / 16)`，提供约 16 mm 量化步长；
- `distance_code = 10'h3FF` 表示无效点；
- `quality_class` 为 0 至 3 的质量等级，不直接暴露全部 6 bit 原始质量；
- 分包 `P=0` 对应 0 至 55 度，`P=5` 对应 300 至 355 度。

默认完整建图圈上报频率为 1 Hz。按 6 行、每行 50 字节计算，纯 UART 数据约
为 3000 bit/s。实机 CH9141K 直连测试表明，除 `@R` 外还并发发送 `@S/@L/@V`
和心跳时，约 1.1 kB/s 已会出现通知侧丢字节，因此这里按实测吞吐而不是
115200 bit/s 的理论 UART 上限留出余量。提高到 2 Hz 或 5 Hz 前必须重新测量
完整圈率、CRC 错误和截断帧数量。

## 6. 精度提升算法

### 6.1 雷达安装外参

必须测量并固化：

- 雷达旋转中心相对车体中心的 `lidar_x_mm`、`lidar_y_mm`；
- 雷达 0 度方向相对车头的 `lidar_yaw_q`；
- 安装倾斜、上盖或车体遮挡对应的永久无效角区间。

服务器先把雷达点变换到车体坐标，再使用该点采样时刻的车体位姿变换到地图
坐标。不能假设雷达位于车辆中心，也不能用一圈结束时的单个位姿处理整圈。

### 6.2 静态测距与角度标定

使用平整墙面，在 500、1000、2000、3000 和 4000 mm 距离分别静止采集：

1. 统计每个角度箱的有效率、中位误差和 95% 误差；
2. 求统一距离偏置和随距离变化的线性修正，先在服务器侧应用；
3. 让车体分别以 0、90、180、270 度正对同一墙面，求雷达零角偏置；
4. 标记长期被车体、支架或线束遮挡的角度箱；
5. 不用单次测量结果直接写入参数，至少重复三组并取中位参数。

### 6.3 运动畸变补偿

一圈扫描不是同一时刻完成。对第 `i` 个 5 度点，按圈周期估算其圈内采样时间，
再插值该时刻的 `x/y/yaw`：

```text
t_point = t_scan_start + i / 72 * scan_period
```

短时姿态优先使用双 BMI088 和 PMW3901 里程计；UWB 只负责低频全局校正。
运动传感器尚未完成标定时，允许显示即时雷达图，但移动状态下不得把点永久
写入地图。

### 6.4 服务器栅格融合

- 默认栅格边长 50 mm；
- 对每个有效点，从雷达原点到命中点做射线遍历；
- 射线经过格降低占用概率，命中格提高占用概率；
- 使用有上下限的整数 log-odds，避免单个异常点永久污染地图；
- 低质量点降低命中权重，超量程点只更新有限范围内的空闲区域；
- 只有 UWB/融合位姿质量合格且时间新鲜时才写永久地图；
- 墙线拟合、回环比较和地图存盘均在服务器执行，不消耗 FPGA 资源。

## 7. 实施顺序

1. **离线基线**：用 CH340 或厂商 USB 接口保存原始雷达点，测量实际转速、
   点数、质量分布、遮挡角和静态误差；
2. **独立 FPGA 仿真**：给 `lidar_map_sampler` 回放节点流，验证 72 箱选择、
   无效值、分包、CRC、漏包和扫描序号；
3. **独立硬件固件**：只运行雷达接收和 `@R` 输出，统计 BLE/UWB 丢包率；
4. **资源复核**：主工程先降低当前 LUT 基线，再接入只读地图数据，禁止直接
   参与 C5 控制；
5. **服务器回放建图**：使用记录文件重复运行，验证相同输入产生相同地图；
6. **静止实测**：先建固定墙面和矩形场地；
7. **低速移动实测**：运动补偿通过后再允许地图持续累积；
8. **自动巡航**：地图稳定后才能用于路径规划，实时停车仍以 FPGA 安全路径
   为最高优先级。

## 8. 验收证据

每次版本至少保存：

- 原始 UART/解析 CSV、测试环境尺寸和雷达安装尺寸；
- 每圈 72 箱有效率、质量分布、CRC 和漏包统计；
- 静态墙面距离误差和直线残差；
- 静止地图漂移、原地旋转重合误差和闭环返回起点误差；
- FPGA 增量 LUT/FF/BRAM、ABC9 时间、Roplace 时间和时序余量；
- 同一数据集的服务器回放结果与参数版本。

只有这些证据齐全后，才能把“提高了建图精度”写成实测结论。在此之前应表述
为“增加了 5 度角分辨率和精度改进机制”。

## 9. 2026-08-04 工具链验证结果

当前实现已完成以下离线验证：

- `tb_lidar_map_sampler.v`：72 箱选择、无效值、六分包、分包间隔和 CRC-8 通过；
- `tb_bt_route_uart_map.v`：完整 50 字节 `@R` UART 行及发送完成握手通过；
- `tb_linkpg_uwb_bridge.v`：现有 UWB 命令、ACK 和遥测转发回归通过；新增
  49 字节 `@R` 正文边界测试确认其封装为单个长度 `0x31` 的 F1 分片，首尾
  数据一致且 `telemetry_drop_count=0`；
- 服务器测试：`@R` 严格长度/CRC 检查、乱序六包重组和 72 点事件发布通过；
- 完整 Robei/Yosys `synth_xilinx -abc9`：退出码 0，检查为 0 个结构问题；
- Robei `Roplace`：第 4 轮路由过用资源收敛到 0，成功生成 routed JSON 和 FASM；
- Robei 打包：成功生成独立验证用 frame 和 bit 文件，未覆盖稳定固件。

独立验证 bit 位于 `little_car/build/lidar_map_validation/top.bit`，SHA-256 为
`236F40932E2B08B20ED41D46AC341377C5588C0A7C44E077AC5ECBDBCB1992CE`。
原 `little_car/build/top.bit` 仍是 2026-07-15 的稳定固件，未被覆盖。

完整 Roplace 资源为 42,522/65,200 `SLICE_LUTX`（65%）、
6,326/65,200 `SLICE_FFX`（9%）、3,739/8,150 `CARRY4`（45%）和
2/150 `RAMB18E1`。ABC9 用时约 342 秒，Roplace 用时约 262 秒。

当前 `top.xdc` 没有 `create_clock`，Roplace 因而沿用 12 MHz 默认目标；其
“PASS at 12 MHz”不能替代板载 50 MHz 的正式时序收敛证明。此次结果可以证明
Robei 全链路可综合、可布局、可布线和可打包，但上板后的测距误差、丢包率、
50 MHz 时序裕量和实际建图精度仍必须通过硬件采集固化证据。

额外使用同一网表执行 `Roplace --freq 50` 时，路由仍在第 4 轮收敛到 0 个
过用资源并生成完整 routed JSON，但因时序失败返回退出码 1：系统时钟域最高
频率为 35.94 MHz，像素时钟域为 29.61 MHz，250 MHz 串化时钟域为
356.00 MHz。系统域最慢路径位于既有 `c5_motor_frame_driver`，像素域最慢路径
位于既有 `gui_route_renderer`，均不经过新增 `lidar_map_sampler`。因此本次
升级已证明没有造成布局或路由不收敛，但不能声称整个历史工程已经在 50 MHz
下完成静态时序闭合；后续应单独对 C5 组合链和 GUI 渲染链做流水化，不能把
该问题归因于 72 点雷达缓存。
