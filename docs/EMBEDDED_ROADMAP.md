# 面向 Linux / AI / 机器人的扩展路线

本页是后续学习与工程计划，**不是本项目已经完成的功能列表**。

## 现有项目能够支撑的能力

| 求职关联 | 当前可展示证据 |
| --- | --- |
| 软硬件联调 | FPGA 顶层接口、UART、传感器诊断、C5 控制和波形验证 |
| 通信与可靠性 | BLE 通知/写入、帧解析、CRC、分段重组、数据新鲜度和命令看门狗 |
| 嵌入式 C/C++ | ESP32-S3 网关、UART 接入、启动/重试状态机 |
| Linux 用户态与网络 | Python/FastAPI 服务、WebSocket、Docker 部署入口与测试 |
| 机器人感知基础 | 雷达角度栅格、地图参考算法、四标签位姿与几何约束 |
| 工程方法 | 配置生成、模型/Verilog 转换、单元测试、VCD 哈希、GitHub Actions |

## 建议按顺序扩展

1. **Linux C/C++ 设备通信**：用 `termios`、`poll/epoll` 和线程安全队列实现 UART 适配层；为半帧、粘包、超时、断线和重连补充故障注入测试，保留协议兼容。
2. **系统服务化**：增加配置校验、结构化日志、systemd 服务、健康检查和资源监控；验证重启、断电和网络恢复。
3. **ROS 2 适配**：在独立适配包中发布雷达与位姿，明确时间戳、单位和 TF；先使用真实数据回放，再接入机器人导航组件。不要把参考地图算法直接称为已交付 SLAM。
4. **边缘 AI**：在适配硬件上加入独立的视觉/目标检测模块，记录模型来源、精度、延迟与内存；AI 感知输出不直接绕过车辆停止机制。
5. **内核驱动基础**：另建小实验学习 GPIO/I2C/SPI、设备树和驱动生命周期，并明确哪些工作在内核态，哪些在用户态。

每一步交付代码、环境、数据和测试报告后，再将相应能力写入简历。当前不要填写尚未实现的 ROS 2、内核驱动、AI 推理或实测性能。
